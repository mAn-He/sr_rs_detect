## 유효 마스크와 NoData 규칙 (M1~M8, CLAUDE.md)
- 선택: 유효 마스크는 train 칩 footprint 합집합(픽셀값 아님)을 HR·LR 격자에 래스터화. 무효 픽셀은 train 유효 픽셀의 밴드별 8비트 평균으로 채우고 SR 출력(S0~S8)에도 같은 값으로 다시 덮어쓴다. 평가 영역은 footprint를 안쪽으로 9.6 m(LR 8px) 줄인 영역이며, 폴리곤 면적의 50% 이상이 평가 영역 밖인 GT·예측은 TP/FP/FN에서 모두 제외한다. 제외 폭 0/8/16 LR px 민감도를 summary와 README에 싣는다. 화질·엣지 지표는 평가 영역 안에서만, LPIPS는 spatial 맵의 마스크 평균. train·val 타일은 유효 비율 25% 이상만, test는 전부 처리 후 마스크로 평가. 백분위·phaseCorrelate·Canny 임계값은 유효 픽셀만으로 계산.
- 대안: 픽셀값 0을 NoData로 판단, 0으로 채움, 무효 영역을 평가에 포함
- 이유: 픽셀값 0은 실제 어두운 화소와 구분되지 않는다. 0 채움은 강한 가짜 경계를 만들어 SR 아티팩트·거짓 양성·엣지 지표를 오염시킨다. 평균 채움과 SR 후 재덮어쓰기로 모든 경로의 무효 영역을 같게 만들고, 9.6 m 안쪽 buffer로 경계 부근 리샘플·SR 번짐을 평가에서 뺀다. 민감도로 buffer 폭 의존성을 확인한다.

## MS 동서 화소 크기 메타데이터 정정
- 근거: MS 칩은 163 px를 칩 범위(650 PS px)에 맞춰 동서 화소 크기를 1.0766871e-5°로 적었다. ECC 아핀(1,168칩)으로 추정한 실제 동서 간격은 1.080065e-5°(중앙값, IQR 1.079844e-5~1.080306e-5, 평균 95% CI 1.080064e-5~1.080125e-5)로 4×PS(1.08e-5°)와 +0.006% 차이(기준 0.1% 이내), 표기값과는 +0.31% 차이다.
- 1차 시도(서쪽 모서리 고정): G2에서 동서 화소 크기만 4×PS로 바꾸고 원점 유지. 칩 내부 동서 기울기는 사라졌지만(좌우 절반 차 −0.234 → +0.003 MS px) 칩 중심 동서 오프셋이 +0.207 → +0.441 MS px(IQR +0.138~+0.632)로 커져 G5 초과 블록 9 → 39/168. 폐기.
- 2차 검증(scripts/diag/g5_phase.py): 중심 고정(가설 A)은 기울기를 없애고(−0.004) 중심 dx를 유지했지만 IQR 폭 0.52가 남았다. 전역 칩 격자 열 홀짝으로 나누면 중심 dx가 짝수 열 −0.125 [−0.168, −0.065], 홀수 열 +0.390 [+0.342, +0.447]로 0.515 MS px 갈렸다(가설 C). 650k PS px ÷ 4 = 162.5k라 원래 MS 격자에 대한 칩 원점 위상이 열마다 0 / 0.5 MS px로 바뀐다.
- 선택(최종): 동서 화소 4×PS, MS 칩 원점 = 칩 원점 − 2 PS px × (k mod 2), k = 전역 칩 격자 열 번호(chip_index의 minx 최솟값 −115.3075176°에서 센다). 칩별 측정값을 쓰지 않는 기하 규칙이다. 남북은 정정하지 않는다. 픽셀값은 바뀌지 않고 geotransform만 바뀐다.
- 홀수 열에 −2 PS px를 적용한 근거: 원래 MS 격자 원점을 전역 칩 격자 서쪽 끝(열 0의 원점)으로 두면 기하적으로 홀수 열이 2 PS px 어긋난다. 데이터로도 홀수 열 적용 시 칩별 중심 dx 잔차 IQR 폭 0.106(+0.094~+0.200), 짝수 열 적용 시 1.006(−0.373~+0.633)이라 홀수 열이 맞다.
- 대안: 정정하지 않음(G5 초과 9/168), 서쪽 모서리 고정(39/168), 칩별 측정값으로 원점 보정(규칙 위반)

## 평가 세부 정의 (2026-10-29 제안, 2026-10-30 사용자 결정 반영)
- 원칙(사용자 결정): 운영 conf와 타일 병합 IoU는 val 블록에서 D_HR로 정해 모든 방법에 고정한다. test로 정하지 않는다.
- 선택:
  - AP용 예측은 conf ≥ 0.001(Ultralytics val 기본값).
  - 운영 conf(거짓 양성 수, 면적 구간별 재현율): D_HR은 HR val, D_LR은 LR val에서 F1 최대 conf. 계산은 Ultralytics ap_per_class와 같다(1000점 conf 격자, F1 곡선 0.1 평활 후 최대). 지리 평가와 같은 조건(병합 후, 평가 영역·M4 제외, 제외 폭 8 LR px)에서 구한다. SR 행(D_HR on SR)은 D_HR 값을 쓴다.
  - 타일 병합 NMS(cv2.dnn.NMSBoxesRotated, 블록마다): HR val에서 IoU 0.5와 0.7을 비교한다. 비교 값은 AP50과 중복 쌍 비율(운영 conf 이상 병합 예측끼리 회전 IoU > 0.3인 쌍의 수 ÷ 예측 수). 규칙: AP50 차가 0.005 이내면 중복 쌍 비율이 낮은 쪽, 아니면 AP50이 높은 쪽(사용자 지시 "나은 쪽"을 실행 규칙으로 정한 것). D_LR의 운영 conf는 고른 IoU로 병합한 뒤 구한다.
  - max_det: train·val 타일당 GT 최대 개수 × 3과 3000 중 큰 값(GT 최대 231 → 3000). 추론(val·test)에 같은 값을 쓰고, test 타일 GT 최대 개수가 이 값을 넘지 않는지 assert한다. 스모크에서 기본값 300이 타일마다 꽉 차 상한에 걸려 처음에는 최소 1000으로 정했으나, 본 실행 HR val(conf 0.001)에서 101타일 중 33타일이 1000에 걸렸다(잘린 예측은 모두 conf < 0.011). 사용자 결정(2026-10-30)으로 3000으로 올리고(그래도 걸리면 5000) val 예측·보정만 다시 했다. 이유: SR 방법마다 저신뢰도 예측 양이 달라 상한 절단이 방법 간 AP50 차이에 섞일 수 있다. 상한에 걸린 타일 수는 results/det_calibration.json의 tiles_at_max_det, test는 det_timing.csv에 남긴다. D_HR·D_LR 학습 중 val(최적 가중치 선택)은 max_det 1000으로 돌았다(학습은 다시 하지 않음, results/det_D_*.json args).
  - AP50은 Ultralytics compute_ap과 같은 101점 보간(사용자 승인). 매칭은 conf 내림차순 탐욕, UTM에서 예측 OBB와 GT 폴리곤의 최소 회전 사각형(cv2.minAreaRect) 사이 회전 IoU ≥ 0.5(사용자 승인).
  - 부트스트랩은 test 블록 복원추출. GT·예측은 중심점이 든 test 블록에 속하며, 같은 표본으로 방법과 경로 1의 차이(gain)를 계산한다.
  - 평가 영역은 footprint 안쪽 제외 폭 ∩ 분할 블록 ∩ 사용 타일. test는 모든 타일을 쓰므로 블록과 같고, val은 유효 25% 미만 타일이 없어 그 영역을 뺀다.
- 대안: Ultralytics 기본값(conf 0.25, NMS IoU 0.7, max_det 300) 그대로, 타일 단위 Ultralytics val의 F1 최대 conf, 전역 NMS
- 이유: 기본값은 이 데이터에 맞춘 값이 아니고, test에서 정하면 test 결과가 낙관적으로 치우친다. 타일 단위가 아니라 병합 후 지리 평가 조건에서 정해야 test 평가와 같은 조건이다.
